ZEN TIDY — STEP-BY-STEP DIAGNOSIS
=================================
Goal: find out exactly which layer is failing. Do the CONSOLE TEST first;
it bypasses the loader entirely and tells us if the core works.

--------------------------------------------------
A. ENABLE + OPEN THE RIGHT CONSOLE
--------------------------------------------------
Zen disables DevTools by default, so:
1. Go to about:config
2. Set:  devtools.chrome.enabled = true
         devtools.debugger.remote-enabled = true
3. Open the BROWSER console:  Ctrl + Shift + J
   (NOT F12 — that is the web console and CANNOT see gBrowser.)
   If Ctrl+Shift+J does nothing, enable Developer Tools in Zen Settings first,
   then retry.

If you cannot get a Browser Console with a command input line, tell me —
that itself is the blocker.

--------------------------------------------------
B. SET YOUR API KEY (needed only for the actual Tidy, not for the button)
--------------------------------------------------
about:config →  extensions.zentidy.apikey  (String) = sk-or-v1-...  (OpenRouter key)

--------------------------------------------------
C. RUN THE CONSOLE TEST
--------------------------------------------------
Paste the ENTIRE contents of JS/zen-tidy.uc.js into the Browser Console
input and press Enter.

Now read the log lines prefixed with [Zen Tidy]. Match what you see:

EXPECTED (success):
   [Zen Tidy] STARTING ...
   STEP 1 — execution context
      location.href = chrome://browser/content/browser.xhtml
   STEP 2 — resolving browser window ... OK
   STEP 3 — capabilities
      gBrowser.addTabGroup is function: true
   STEP 4/5 — prefs + tab list
   STEP 6 — locating a place for the button
      #zen-sidebar-top-buttons-customization-target: FOUND
      ✅ button added to: #...
   DONE.
=> A purple "✨ Tidy" button is now at the TOP OF THE SIDEBAR.

FAILURE PATTERNS — what each means:

1) You see NOTHING at all (no [Zen Tidy] lines):
   - The console isn't executing the paste, or it's the wrong console.
   - Re-check step A (devtools.chrome.enabled, Ctrl+Shift+J).

2) "FATAL: no gBrowser available":
   - Console is evaluating in a content/page context.
   - In the console input toolbar there may be a context selector — set it to
     the parent/chrome window. Then re-paste.

3) "gBrowser.addTabGroup is function: false":
   - This Zen build doesn't expose the tab-group API. Tell me — we switch to
     Zen's folder API instead.

4) All FOUND lines say "missing" and you see "FLOATING fallback":
   - The sidebar element IDs differ in your layout. A purple button appears
     in the TOP-RIGHT CORNER of the window instead. Click it — it still works.
   - Send me the STEP 6 log so I can target your real sidebar element.

5) Button appears, but clicking it logs an API error (STEP shows HTTP 401/403):
   - Bad/missing API key. Fix extensions.zentidy.apikey.

--------------------------------------------------
D. AFTER the console test works → make it permanent
--------------------------------------------------
A console paste is temporary (gone on restart). For persistence you MUST
install a loader:
   - fx-autoconfig: https://github.com/MrOtherGuy/fx-autoconfig
   - or Sine:       https://github.com/CosmoCreeper/Sine
Then put zen-tidy.uc.js in  <profile>/chrome/JS/  and
about:support → Clear startup cache → restart.

When it loads at startup you'll again see the [Zen Tidy] STARTING log in the
Browser Console. If you don't, the loader isn't running the file (wrong
folder, or loader not installed).

--------------------------------------------------
MANUAL CONTROLS (after pasting, type in console)
--------------------------------------------------
   zenTidy.diagnose()    // re-print capability summary
   zenTidy.addButton()   // retry placing the button
   zenTidy.tidy()        // run the tidy now without the button
